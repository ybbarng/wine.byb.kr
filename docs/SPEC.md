# wine.byb.kr — 전체 스펙 문서

> 상태: 초안 v0.1 (2026-08-20)
> 작성 목적: 개발 착수 전 전체 그림을 합의하기 위한 스펙. 확정이 아니라 논의의 출발점이다. "결정 필요" 표시가 붙은 항목은 함께 정한 뒤 개발을 시작한다.

---

## 0. 한 줄 요약

와인 한 병을 검색하면 그 와인이 **어디서, 어떤 포도로, 어떤 맥락에서** 만들어졌는지를 지도와 함께 흥미롭게 보여주고, **이 가격이 합리적인지** 판단을 돕고, **내가 마신 기록**을 쌓아 나가는, 와인 테마의 인터랙티브 웹사이트.

---

## 1. 배경과 동기

- `~/personal/notes/HJYB/취미/` 아래에 그동안 손으로 정리해 온 와인 기록이 있다.
  - **시음 노트 29개** (`와인 시음노트/`): 날짜·구매가격·구매일·빈티지·음용일.
  - **와인 상세 DB** (`와인 품종정보DB/품종 정보 DB/`): 국가·도수·등급·생산자·위치·종류(레드/화이트/로제/스파클링/샴페인)·품종(블렌딩 비율)·시음 노트 링크.
  - **가성비 추천 / 유튜브 채널 추천**: 유튜버·쇼츠에서 모은 추천 와인과 취향 메모.
- 노션 → Obsidian 마크다운으로 옮겨온 상태라 **정형 데이터로 재활용하기 좋다.** 이 기록이 초기 시드 데이터가 된다.
- 손으로 정리하는 게 번거롭고 재미없어서 방치했다. → **정리 자체가 재미있고, 검색만으로 배움과 판단이 따라오는** 도구가 있으면 다시 하게 될 것이라는 게 이 프로젝트의 가설이다.

## 2. 목표와 비목표

### 2.1 핵심 목표 (사용자가 제시한 4가지)

1. **와인 탐험 (Explore)** — 와인을 검색하면 생산지로 지도가 부드럽게 이동하고, 지역·포도·와이너리 특성과 흥미로운 정보를 다양하게 제공. "이 와인이 어디 것이고, 어떤 포도로 만들었고, 마실 때 무엇을 눈여겨보면 좋은지"를 검색 한 번으로 알게 한다.
2. **가격 분석 (Value)** — 특정 가격에 샀을 때(또는 살까 말까 할 때) 그게 합리적인지 판단을 돕는다. 편의점/마트 할인 와인의 가치 비교에 쓴다.
3. **기록 (Cellar/Journal)** — 내가 마신 와인을 기록하고, 몇 번 마셨는지·전에 마셨는지·그때 어땠는지·그때 가격은 얼마였는지 되짚어 본다. **기록은 나만 작성, 조회는 누구나.**
4. **학습 (Learn)** — 와인 산업 전반을 공부하는 페이지. 지루한 줄글이 아니라 풍부하고 인터랙티브한 자료.

### 2.2 경험 목표 (분위기)

- 전체적으로 **와인 테마**. 화려하고 재미있고 신기한 사이트.
- 최신 웹 기술을 적극 활용: 부드러운 지도 이동 애니메이션, 스크롤 연동 인터랙션, 3D/파티클 등 "와" 하는 순간.
- 단, **화려함이 정보 전달을 방해하지 않게** 한다. 애니메이션은 "이해를 돕는 연출"이어야지 장식이 목적이 아니다. (성능·접근성·`prefers-reduced-motion` 고려)

### 2.3 비목표 (지금은 안 하는 것)

- 다중 사용자 계정/소셜 기능(팔로우, 댓글, 공유 셀러). 나는 유일한 편집자다.
- 커머스(판매, 결제, 장바구니). 가격은 "참고·비교"용이지 판매가 아니다.
- 모바일 네이티브 앱. 반응형 웹으로 충분.
- 완벽하게 정확한 전 세계 와인 시세 실시간 크롤링(법적/기술적 부담). 1차는 큐레이션 + 사용자 입력 시세 기반.

## 3. 사용자와 권한

| 역할 | 할 수 있는 것 |
| --- | --- |
| **방문자 (누구나)** | 와인 탐험, 가격 분석 조회, 내 기록(셀러/저널) 조회, 학습 페이지 |
| **관리자 (나)** | 위 전부 + 와인/지역/품종 DB 편집, 시음 기록 작성/수정, 시세 입력, 학습 콘텐츠 편집 |

- 인증 방식: 참고 프로젝트(`francais-tres-facile`)와 동일하게 **단일 `ADMIN_PASSWORD` 환경변수 + 세션 쿠키** 방식으로 시작.
  - 로그인 폼 → 비밀번호 검증 → HttpOnly 서명 쿠키 발급 → 편집 API는 미들웨어에서 쿠키 검증.
  - 편집 UI(버튼/폼)는 인증 상태에서만 노출. 편집 API는 서버에서도 반드시 재검증(클라이언트 숨김만 믿지 않음).

### 3.1 회사 동호회 공유 방향 (결정됨: 단일 인스턴스 + 확장 여지)

회사 와인 동호회에 공유할 것을 염두에 두되, **지금은 단일 인스턴스(나만 편집 / 누구나 조회)로 시작**한다. 커뮤니티화(회원별 셀러·공유)는 하지 않는다.

- **왜**: 나 혼자서도 기록을 방치했던 만큼, 먼저 내가 매일 쓰는 도구인지부터 검증한다. 멀티유저는 인증·프라이버시·운영 부담이 크고 되돌리기 어렵다. 포크형은 비개발자 회원에게 진입장벽이 높다.
- **단, 데이터 모델은 멀티유저 확장을 막지 않게 설계**한다. `TastingNote` 등 "사람이 만든 기록" 계열에는 처음부터 `author`/`owner` 개념(현재는 상수 `admin`)을 두어, 나중에 회원별 셀러로 승격할 때 스키마 대이동이 없게 한다.
- 그 사이 동호회 공유는 "내 셀러를 보여주는 공개 링크"로 충분히 커버된다.
- **미래 승격 경로(참고)**: 반응이 좋으면 → 계정(OAuth 등) 도입 → `owner=admin` 기록을 유지한 채 회원별 기록 추가 → 공용 엔티티(Wine/Region/Grape/Producer)는 그대로 공유. 이 순서면 재작업이 작다.

## 4. 정보 구조 & 페이지

```
/                     홈 — 검색 히어로 + 최근 마신 와인 + 지도 미리보기
/wine/[slug]          와인 상세 (탐험의 핵심 화면)
/explore              지도 중심 탐험 (전 세계 산지 브라우징)
/value                가격 분석 (한 와인의 시세 분포 + 가치 판단)
/cellar               내 셀러/저널 — 마신 기록 타임라인·통계 (조회 공개)
/cellar/[id]          개별 시음 기록
/learn                학습 허브
/learn/[topic]        학습 개별 토픽 (인터랙티브)
/grape/[slug]         포도 품종 상세
/region/[slug]        와인 산지 상세
/producer/[slug]      생산자/와이너리 상세
/admin/*              편집 화면 (인증 필요)
```

### 4.1 홈 `/`
- 큰 검색창(히어로). "도멘 데 아르디에 앙주 블랑 레 쁘디 갸르" 같은 자유 입력.
- 배경에 은은한 와인 테마 연출(라벨/포도밭/지도).
- 최근 마신 와인, "오늘의 품종", 지도 미리보기(내가 마셔본 와인의 산지 핀).

### 4.2 와인 상세 `/wine/[slug]` — **가장 중요한 화면**
검색 결과로 진입. 스크롤을 내리며 이야기가 펼쳐지는 구조.

1. **히어로**: 와인 이름(한/영/원어), 병 이미지/라벨, 종류·빈티지·도수·생산자·지역 요약 배지.
2. **지도 이동 연출**: 진입 시 세계 지도에서 해당 산지로 **부드럽게 fly-to** 애니메이션. 지역 경계 하이라이트. (예: 앙주 → 루아르 밸리로 확대)
3. **지역 특성**: 기후, 토양, 이 지역이 유명한 이유, 대표 스타일.
4. **포도 품종**: 블렌딩 비율을 시각화(도넛/막대). 각 품종의 특성(산도·타닌·바디·향 프로필) → `/grape/[slug]` 링크.
5. **와이너리 특성**: 생산자 소개, 규모, 철학, 대표 와인.
6. **시음 포인트**: "이 와인을 마실 때 눈여겨볼 점" — 산도/타닌/과실/오크/미네랄리티 등을 흥미롭게 짚어줌. 어울리는 음식(한식 매칭 강조 — 기존 메모에 한식 페어링 취향이 많음).
7. **가치 판단**: 내가 산 가격 vs 시세대 → `/value` 요약. "이 가격이면 괜찮다/비싸다" 감각.
8. **내 기록**: 이 와인을 마신 적이 있으면 그 기록(날짜·가격·감상)을 함께. 없으면 "아직 안 마심".
9. **유사/추천 와인**: 같은 품종·같은 지역·비슷한 가격대·비슷한 스타일 추천.

### 4.3 탐험 `/explore`
- 전체 화면 인터랙티브 지도. 산지 클러스터 핀. 필터(국가/품종/종류/가격대/내가 마신 것만).
- 핀 클릭 → 지역 상세 사이드패널. "이 지역 대표 품종/스타일".

### 4.4 가격 분석 `/value`
- 와인 선택 → 알려진 시세 포인트(구매 기록 + 수동 입력 시세 + 가능하면 외부 참고)를 분포로 표시.
- "당신이 본 가격 35,000원"을 분포 위에 놓아 **백분위/합리성** 표시.
- 빈티지별·시점별 가격 추이(내 구매 기록이 쌓이면 자동).
- **편의점 할인 판단**: 가격 입력 → 즉시 "가치 있음/보통/비쌈" 신호.

### 4.5 셀러/저널 `/cellar`
- 마신 와인 타임라인(달력/리스트). 통계: 총 병 수, 품종 분포, 국가 분포, 평균 가격, 재구매 와인.
- 검색·필터. 각 기록은 사진·평점·메모·페어링·가격 포함.
- **조회 공개, 작성은 관리자만.**

### 4.6 학습 `/learn`
- 토픽 카드 허브. 각 토픽은 인터랙티브:
  - "포도 품종 지도" (인터랙티브 계통도/향 프로필 레이더)
  - "와인 등급 체계" (프랑스 AOC/이탈리아 DOC/... 대화형 비교)
  - "떼루아란?" (기후·토양·경사 슬라이더로 결과가 바뀌는 시뮬레이션)
  - "라벨 읽는 법" (실제 라벨에 마우스 올리면 각 요소 설명)
  - "테이스팅 스텝" (색→향→맛 단계별 인터랙션)
- **결정 필요**: 학습 콘텐츠 초기 토픽 우선순위.

### 4.7 품종/지역/생산자 상세
- 재사용되는 엔티티 페이지. 와인 상세에서 링크로 진입. 해당 엔티티에 속한 "내가 마신 와인" 목록 포함.

## 5. 데이터 모델 (초안)

기존 마크다운 필드를 정규화한 스키마. Prisma + SQLite(libsql) 기준.

### 5.1 핵심 엔티티

**Region (지역)** — 계층 구조 (국가 > 광역 > 세부 AOC)
- `id, slug, name_ko, name_local, parent_id`
- `country, level(country|region|subregion|appellation)`
- `latitude, longitude` (fly-to 목표점)
- `boundary_geojson` (선택: 경계 폴리곤)
- `climate, soil, description_ko, signature_styles`

**Grape (품종)**
- `id, slug, name_ko, name_local, aliases`
- `color(red|white), body, acidity, tannin, sweetness, aroma_profile(태그[])`
- `description_ko, typical_regions(→Region[])`

**Producer (생산자/와이너리)**
- `id, slug, name_ko, name_local, region_id, description_ko, founded, philosophy`

**Wine (와인)** — 하나의 "제품"
- `id, slug, name_ko, name_local`
- `producer_id, region_id, type(red|white|rose|sparkling|champagne|dessert|fortified)`
- `abv(도수), classification(등급 예: AOC, IGT, Grand Cru 4등급)`
- `blend`: `[{grape_id, percent}]` (블렌딩 비율)
- `notes_ko, food_pairing(태그[]), image_url`
- `external_refs`: Vivino/Wine-Searcher 등 참고 링크

**Vintage (빈티지)** — 선택. 같은 와인의 연도별.
- `id, wine_id, year, note`

**TastingNote (시음 기록)** — 내가 마신 기록 (기존 시음노트 29개)
- `id, wine_id, vintage_year`
- `drank_on(음용일), purchased_on(구매일), purchase_price, purchase_place(편의점/마트/...)`
- `rating(내 평점), body_text(감상), food_paired, photos[]`
- `owner(현재는 상수 "admin" — 3.1의 멀티유저 확장 여지), is_public(default true)`

**PriceObservation (시세 관측)** — 가격 분석용
- `id, wine_id, vintage_year, price, currency, source(구매기록|수동입력|외부), observed_on, place, url`

**LearnTopic (학습 토픽)**
- `id, slug, title_ko, summary, content(MDX/JSON), interactive_type, order`

### 5.2 마이그레이션(기존 노트 → DB)
- 기존 `와인_all.csv`, 시음노트 마크다운, 상세 DB 마크다운을 파싱하는 **일회성 시드 스크립트** 작성.
- 프랑스어 날짜("19 août 2025"), "35 920 ₩", "14,5"(쉼표 소수점) 등 정규화 규칙 필요.
- 지역 문자열("타란티노, 만데리아, 뿔리아 Puglia")을 Region 계층으로 매핑(수작업 보정 불가피).
- `scripts/seed-from-notes.ts` 형태. 참고 프로젝트의 sync 스크립트 패턴 재사용.

## 6. 데이터 소싱 전략 (가장 큰 리스크)

목표 1·2의 품질은 **와인 정보와 시세 데이터를 어디서 얻느냐**에 달려 있다. 현실적 단계 전략:

### 6.1 와인/지역/품종 정보
- **1단계 (지금)**: 내가 마신 와인 중심의 큐레이션 DB. 지역·품종 정보는 직접 작성 + 신뢰 출처 정리.
- **2단계**: **LLM 보강** — 와인/지역/품종 설명 초안을 Claude API로 생성하고 **내가 검수 후 저장**(자동 노출 금지, 환각 위험). "AI 초안 → 관리자 승인" 파이프라인.
- **참고 가능한 데이터**:
  - 지역 좌표/경계: 자체 구축(주요 산지 수십 개면 커버). 공개 GeoJSON(국가·프랑스 AOC 등) 부분 활용.
  - 품종 계통: 공개 자료 정리.
  - 외부 API(대부분 유료/제약): Vivino(비공식), Wine-Searcher, Global Wine Score 등 — **직접 크롤링은 지양**, 링크 참조 위주.
- **결정 필요**: 커버리지 범위. "내가 마셔본 것 + 사고 싶은 것" 중심(수백 종)으로 시작하고 검색 시 없으면 "관리자 추가 대기"로 두는 게 현실적.

### 6.2 시세 데이터
- **1단계**: 내 구매 기록이 곧 시세 관측치(PriceObservation). 편의점/마트 할인가를 볼 때마다 수동으로 한 건 입력 → 자연스럽게 시세 분포가 쌓임.
- **2단계**: 국내 와인 앱/샵(데일리샷·와인나라 등) 공개 가격을 **참고 링크**로. 크롤링은 약관·부하 문제라 신중히(캐시·저빈도).
- 판단 로직: 같은 와인의 관측치 분포에서 입력 가격의 백분위 → 신호. 관측치가 적으면 "표본 부족" 정직하게 표시.

## 8. 추가로 제안하는 기능 (내가 고민한 보강)

핵심 4가지 위에 얹으면 좋을 것들. 우선순위는 함께 정한다.

**탐험/정보 강화**
- **블라인드 모드 / 퀴즈**: 라벨 가리고 "이 와인의 품종·지역 맞히기". 학습과 재미 결합.
- **향/맛 레이더 차트**: 산도·타닌·바디·당도·과실·오크를 한눈에. 와인 간 비교 오버레이.
- **음식 페어링 추천기**: 오늘 먹을 음식 입력 → 셀러/추천에서 어울리는 와인. (한식 페어링 강조 — 기존 취향)
- **"이 와인과 비슷한 것" 추천 엔진**: 품종·지역·스타일·가격 유사도.

**가격/가치 강화**
- **할인 판독기(빠른 진입)**: 편의점에서 폰으로 바로 — 와인명/바코드 입력 → 즉시 가치 신호. 모바일 우선 초경량 화면.
- **가격 추이 그래프**: 내가 같은 와인을 여러 번 사면 자동으로 시계열.
- **"가성비 지수"**: 평점 대비 가격. 기존 "가성비 추천" 노트를 이 지수로 재구성.

**기록 강화**
- **재구매/재음용 감지**: 검색 시 "전에 마셨어요(2025-04-19, 31,920원, ★★★★)" 즉시 표시 — 사용자가 원한 핵심 시나리오.
- **위시리스트**: 마시고 싶은/사고 싶은 와인. 유튜버 추천(비밀이야/양갱 등) 정리를 여기로.
- **연말 결산**: "올해의 와인", 총 지출, 새로 시도한 품종 수 — 기록 동기 부여.
- **빠른 기록 폼**: 사진 한 장 + 가격 + 별점만으로도 기록 완료(진입 장벽 최소화 → 방치 방지).

**학습/기타**
- **인터랙티브 세계 와인 지도**: 국가별 대표 품종·스타일을 지도로 학습.
- **품종 계통 트리**: 품종의 부모/자식·별칭(쉬라=쉬라즈 등) 시각화.
- **다국어 표기 정규화**: "까쇼=까베르네 소비뇽", "멀롯=메를로" 등 별칭 사전(검색 품질 직결).
- **접근성/모션 존중**: `prefers-reduced-motion`에서 애니메이션 대체.
- **OG 이미지/공유 카드**: 와인 상세를 예쁘게 공유(방문자 유입).

## 9. 열려 있는 결정 사항 (개발 전 합의)

1. **커버리지 범위**: "내가 마셔본 것 중심 수백 종"으로 좁게 시작 vs 처음부터 넓게. → 권장: 좁게 시작, 검색 미스는 "추가 대기 큐"로.
2. **지도 타일 소스**: MapTiler 무료 티어 / OpenFreeMap / 자체 호스팅 중 무엇. (키 노출·요금 고려)
3. **AI 보강 도입 시점**: 1단계는 수기, 2단계 Claude 초안+승인. 언제 붙일지.
4. **학습 토픽 우선순위**: 첫 3개 토픽.
5. **디자인 톤**: "화려·신기"의 구체 레퍼런스(무드보드). 다크 와인셀러 톤 vs 밝은 에디토리얼 톤.

### 결정된 사항 (기록)
- **동호회 공유 방향**: 단일 인스턴스(나만 편집/누구나 조회) + 데이터 모델은 멀티유저 확장 여지 유지. (§3.1)
- **인증**: 단일 `ADMIN_PASSWORD` + 세션 쿠키 유지. OAuth는 커뮤니티 승격 시 재검토.
- **배포**: `wine.byb.kr` → byb.kr 서버 → nginx → Traefik → `wine` 컨테이너. main push 시 GitHub Actions 가 이미지를 빌드해 올리고, forced command 배포 키로 서버의 `deploy.sh` 를 실행. (§7 배포, docs/DEPLOY.md)
- **DB**: SQLite 파일 `data/wine.db`, 배포 시 자동 백업.

## 10. 단계별 로드맵 (제안)

**Phase 0 — 토대**
- 프로젝트 스캐폴딩(Next.js 16 + Prisma + Tailwind + biome + lefthook), 참고 프로젝트 설정 이식.
- 데이터 모델 확정 + Prisma 스키마.
- 기존 노트 → DB 시드 스크립트. 관리자 인증(비밀번호+쿠키).

**Phase 1 — 기록(목표 3) 먼저**
- 셀러/저널 조회 + 관리자 작성 폼. 재음용 감지.
- 이유: 데이터가 이미 있고, 내가 매일 쓰게 만들면 나머지 기능의 연료가 된다.

**Phase 2 — 탐험(목표 1)**
- 와인 상세 화면 + 지도 fly-to + 지역/품종/생산자 페이지. 유사 추천.

**Phase 3 — 가치(목표 2)**
- PriceObservation 수집 UI, 가격 분포/백분위, 할인 판독기(모바일).

**Phase 4 — 학습(목표 4)**
- 인터랙티브 토픽 2~3개.

**Phase 5 — 광내기**
- 애니메이션/3D 연출, OG 카드, 연말 결산, 퀴즈, AI 보강.

각 Phase는 작은 의미 단위로 커밋하며 진행.
