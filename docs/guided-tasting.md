# 가이드 시음 (Guided Tasting) — 설계

## 목표

지금의 시음 기록은 "다 마신 뒤 결과를 적는" 폼이다. 가이드 시음은 한 걸음 더 나아가,
**와인을 따는 순간부터 곁에서 안내하며 함께 시음**하게 한다. 각 단계에서 단순히
"보고 평가하세요"가 아니라, **이 와인은 이런 상태일 것이다(예상)** 와 **왜 그런가(근거)**
를 알려주고, 사용자가 그걸 실제 감각과 견주게 한다.

예: "이 와인은 잔 벽을 타고 흐르는 눈물자국(legs)이 굵을 거예요 — 알코올·당분이 높은
편이라서요." → 사용자가 확인/체크.

관련: [[wine-experience-goals]] 의 '신기하다' 목표와 맞물린다. 기록이 곧 학습이 되게.

## 원칙 (결정됨)

- **단일 흐름**: "빠른 기록 모드"를 따로 두지 않는다. 지금의 기록 마법사 한 흐름에 각 단계의
  "예상 + 근거" 안내를 얹는다. 빠른 기록은 "그 흐름을 빠르게 지나가는 것"으로 자연히 해결.
- **예상은 스스로 답한 뒤에 연다**(2026-09-09 결정): 예상을 먼저 보여주면 거기 매몰된다 —
  적힌 색을 보고, 적힌 향을 맡고, 적힌 수준을 고르게 된다(실사용 확인). 그래서 각 단계는
  답하기 전까지 예상을 감추고, 답하면 **그 자리에서** 연다. 단계를 늘리지 않는다.
  - 입력은 계속 열려 있어 고치고 싶으면 고친다. **고치라고 묻지 않는다.**
  - **처음 답을 따로 저장하지 않는다.** 앞뒤 답을 나란히 두면 그 차이가 곧 채점이 되어,
    "맞고 틀림을 매기지 않는다"는 결정과 어긋난다. 데이터도 불필요하게 는다.
  - 안 답하고도 보고 싶으면 "예상 먼저 보기"로 연다(가이드는 강제가 아니므로).
  - **향은 순서만 뒤집어선 안 된다** — 예상 향 칩이 곧 답안지이자 어휘였다. 넓은 향
    팔레트(`aroma-palette.ts`)를 블라인드로 깔고, 고른 뒤에 무엇이 예상이었는지·예상 중
    안 고른 게 무엇인지 알린다. **어휘는 남기고 답안지만 치운다.**
- **가이드는 강제가 아니라 곁들임**: 모든 단계는 건너뛸 수 있고, **와인만 고르면 언제든 저장**
  가능해야 한다(지금 마법사의 "언제든 저장" 구조 유지). 향 확인·맛 평가를 진행 조건으로 걸지
  않는다 — 걸면 빠른 기록이 죽는다.
- **기존 입력은 절대 유실되지 않는다**: 가이드용 새 필드·단계를 추가해도, 이미 입력된 값은
  어떤 편집·배포에도 지워지지 않아야 한다. 편집 저장은 **PATCH 부분 갱신**(온 칸만), 시드는
  **빈 칸만 채움** 규칙을 반드시 지킨다. ([[wine-prod-deploy-data-safety]] — 이 규칙을 어겨
  실제 리뷰가 유실된 사고가 있었다.)

## 흐름 (실제 시음 순서)

마신 기록 마법사(`tasting-note-wizard.tsx`)의 단계 순서를 그대로 잇되, 각 단계에 "예상 +
근거 + 확인" 레이어를 얹는다.

1. **고르기** — 어떤 와인인지 선택(기존).
2. **붓기·색** — "따라서 잔을 기울여 색을 보세요."
   - 예상: 이 와인은 `이런 색`일 거예요. (근거: 종류·품종·빈티지)
   - 확인: 실제 색을 컬러피커로 맞춰 기록(기존 색 단계).
3. **스월·외관** — "잔을 돌려 점도와 눈물자국을 보세요."
   - 예상: 바디가 `가벼움/중간/무거움`이라 눈물자국이 `이럴` 거예요. (근거: 품종 body)
   - 확인: 스월 잔 프리뷰와 비교, 느낌 체크.
4. **향** — "코를 대고 향을 맡아보세요."
   - 예상: `자두·바닐라·후추…` 같은 향이 예상돼요. (근거: 품종 aromaProfile, notesKo)
   - 확인: 예상 향 목록에서 **실제로 난 향을 고른다**(다중 선택) + 자유 메모.
5. **맛** — "한 모금 머금어보세요."
   - 예상: 산도 `높음`, 타닌 `중간`, 단맛 `없음`, 바디 `무거움`. (근거: 품종 acidity/tannin/sweetness/body)
   - 확인: 각 축을 실제로 느낀 정도로 평가(예상과의 일치도) + 예상 맛 체크.
6. **종합** — 별점·가격 대비·재구매(기존 verdict).

## 각 단계의 "예상 + 근거" — 데이터 매핑

근거 데이터는 대부분 이미 있다.

| 단계 | 예상 표시 | 근거(출처) |
|---|---|---|
| 색 | 예상 색 스와치 | `Wine.colorHex` → 없으면 `type`·품종 추정(`wineGlassFor`) |
| 스월·외관 | 바디→점도/legs 문구 | `Grape.body` |
| 향 | 예상 향 태그들 (출처별 묶음) | 품종 아로마(`grape-info`) + 오크(`Wine.oakAging`) + 숙성(빈티지 나이) |
| 숙성 | 나이가 색·향·맛에 남긴 흔적 | `TastingNote.vintageYear`와 마신 해의 차이 |
| 기후 | 산도·바디가 치우칠 방향 | 산지 기후(`region-info`의 climate 문장) |
| 도수 | 무게감·따뜻한 기운 | `Wine.abv` |
| 맛 | 산도·타닌·단맛·바디 게이지 | `Grape.acidity`·`tannin`·`sweetness`·`body` |
| 음식 | 어울리는 음식 | `Wine.foodPairing`(JSON 배열) |
| 한마디 | "마시는 순간 뭘 느껴볼지" | `Wine.notesKo`(이미 이 용도로 큐레이션됨, [[wine-notes-content-direction]]) |

블렌드는 `WineGrape`(품종+비율)로 여러 품종의 향·특성을 비율 가중해 합친다.

**콘텐츠 출처**: `Grape.aromaProfile`·`body`·`acidity`·`tannin`·`sweetness` DB 칸은 비어
있지만, 같은 내용이 이미 `grape-info.ts`에 큐레이션돼 있고 품종 페이지가 이걸 폴백으로
쓴다. 그래서 향·특성 단계는 별도 데이터 보강 없이 `grapeInfo(nameKo)`를 재사용한다
(P2 `expectedAromasFor`가 그렇게 한다). 앞으로 `/add-wine`에서 품종을 추가할 때
`grape-info.ts`에 향·특성을 함께 채우면 가이드 품질이 자연히 올라간다([[wine-add-new-gap]]).

## 저장 (가이드 결과)

가이드에서 사용자가 "확인/평가"한 것을 남기려면 `TastingNote`에 필드가 필요하다.
SQLite라 JSON 문자열로 둔다(기존 `foodPairing`·`aromaProfile`과 동일 방식).

- `aromasConfirmed String?` — 예상 향 중 실제로 맡은 것들(JSON 배열).
- `flavorFelt String?` — 산도/타닌/단맛/바디를 실제로 느낀 정도(JSON: `{acidity:1..5, ...}`).
- (선택) `guidedAt DateTime?` — 가이드로 기록했는지 표시.

기존 필드(`rating`·`colorHex`·`bodyText`·`value`·`repurchase`)는 그대로 재사용.
**주의**: 새 필드는 편집 저장(PATCH 부분 갱신)·시드(빈 칸만 채움) 규칙을 반드시 따른다
— 데이터 유실 사고의 교훈([[wine-prod-deploy-data-safety]]).

## 구현 페이즈

작게 시작해 단계별로 넓힌다(각 페이즈 = 별도 PR).

- **P1 — 색 단계에 "예상 + 근거" 문구**: 기존 색 단계에 "이 와인은 이런 색일 거예요(종류·품종
  때문)" 한 줄과 예상 색 스와치를 붙인다. 저장 변화 없음. 가장 작은 검증.
- **P2 — 향 단계**(완료): 예상 향 태그(`grapeInfo`의 아로마) 표시 + 실제 맡은 향 다중 선택.
  `TastingNote.aromasConfirmed`(JSON 배열) 추가. 위저드에 "어떤 향이 났어요?" 단계(색↔맛 사이),
  시음 상세에 "맡은 향" 칩. 편집은 PATCH 부분 갱신, 예상 목록이 바뀌어도 고른 향은 보존.
- **P3 — 맛 단계**(완료): 축(산도·타닌·단맛·바디)마다 예상 수준을 곁들이고, 실제로 느낀
  정도를 1~5로 받는다. `TastingNote.flavorFelt`(JSON `{acidity,tannin,sweetness,body}`) 추가.
  위저드에 "맛은 어땠어요?" 단계(향↔한마디 사이), 시음 상세에 "느낀 맛" 막대.
  예상 값이 없는 축(화이트의 타닌 등)은 예상을 비워 둬 지어내지 않는다.
- **숙성 반영**(완료, P3 뒤 별도 PR): 빈티지가 있으면 나이를 재(`wineAgeYears`), 어림(≤3년)·
  익어가는 중(4~8년)·무르익음(9년~)으로 나눠 색·향·맛에 안내를 곁들인다. 향은 **출처별로 묶어**
  (`expectedAromaGroups` — "품종에서" / "숙성에서 (N년)") 어디서 오는 향인지 근거까지 보여준다.
  레드 계열과 화이트 계열의 숙성 향이 다르다. 빈티지가 없으면 숙성 얘기를 아예 하지 않는다.
- **오크 반영**(완료): `Wine.oakAging`(none|light|heavy, null=모름)을 신설하고 59종을 큐레이션
  (`scripts/set-wine-oak.ts`, 배포 시드에 등록). 향 단계에 "오크에서" 묶음을 더한다
  (light: 바닐라·토스트 / heavy: +훈연·코코넛·정향). **오크 유래 향을 품종 아로마에서 뺐다**
  (샤르도네의 버터·오크, 템프라니요의 바닐라) — 오크를 안 쓴 샤블리에 "버터·오크"가 뜨던 문제.
  `none`인 와인엔 "오크통을 안 써 과실이 그대로 드러난다"는 한 줄을 대신 붙인다.
  근거 판단은 각 와인 `notesKo` 서술("오크를 안 써서", "미국 오크 숙성")과 등급·양조 관행.
- **기후·도수 반영**(완료): 산지 기후(`climateBand` — [[region-info]]의 기후 문장에서 서늘/온화/
  따뜻을 가름, 세부 산지가 없으면 국가 설명으로 물러섬)와 알코올 도수(`abvNote`)를 향·맛 단계에
  안내로 곁들인다. **예상 값은 바꾸지 않는다** — 기후는 품종 기본값을 흔드는 성격이라 값을
  덮으면 품종 큐레이션과 충돌한다. "서늘한 산지라 산도가 예상보다 또렷할 수 있어요"처럼
  치우칠 방향만 알려준다(점수화를 안 하는 것과 같은 이유).
  59종 중 52종에 기후가 붙고, 이탈리아·프랑스처럼 나라 안에서 기후가 갈리면 판단을 보류한다.
- **P4 — 스월·외관**(완료, 2026-09-09): **단계를 새로 만들지 않고 색 단계에 이었다** —
  실제로도 색을 본 다음 잔을 돌리고, 잔 프리뷰도 이미 그 화면에 있다. 단계가 늘면 빠른
  기록이 느려진다. 눈물자국을 1~5로 받고(`TastingNote.legsFelt`), 표시하면 예상이 열린다.
  예상은 **3D 잔이 쓰는 것과 같은 근거**(`features/glass/legs` 의 `deriveLegs`)에서 나온다 —
  안내와 화면이 어긋나면 "예상대로인지" 눈으로 댈 수가 없다. 도수를 모르는 와인은 이
  블록 자체가 안 뜬다(지어내지 않는다).
- **기록에서도 예상 보이기**(완료): 예상은 **입력할 때만** 보이고 나중에 기록을 다시 열면
  고른 향·느낀 맛만 남아, 배움이 반만 남았다. 시음 상세의 "느낀 맛" 축 옆에 `예상 중간`을,
  "맡은 향" 아래에 *예상했지만 고르지 않은 향*을 덧붙인다 — 다음에 같은 와인을 열 때
  찾아볼 거리가 된다. **맞고 틀림은 여전히 매기지 않는다.**
  예상은 기록한 항목 옆에만 붙인다(이 페이지는 안내가 아니라 기록이므로).
- **블라인드 먼저**(완료, 2026-09-09): 색·향·맛 세 단계 모두 답한 뒤에 예상이 열린다.
  맛은 **축마다 따로** 열려(산도를 표시하면 산도 예상만) 나머지 축이 미리 새지 않는다.
  향은 `AROMA_PALETTE`(12묶음)를 깔고 예상은 답한 뒤에. 팔레트가 예상 향을 모두 담는지는
  `aroma-palette.test.ts` 가 지킨다 — 빠지면 "예상에는 있는데 고를 수 없는 향"이 된다.
- **단맛 근거 순서**(완료, 2026-09-09): 품종만으로 안 정해지는 축이 있었다("드라이~스위트"를
  예상으로 내놓으면 다섯 칸을 다 가리킨다). **라벨 표기 > 종류(디저트) > 품종** 순으로 정하고,
  그래도 못 정하면 예상을 비우고 "라벨을 보라"고 알린다.
- **P5 — 다듬기**: 근거 문구 카피 정리, 블렌드 가중 합성, 품종 콘텐츠 보강 캠페인.

  사용자는 실제 맡은 향을 고르기만 한다. (P3 맛 단계도 같은 방향으로 갔다 — 예상 수준을
