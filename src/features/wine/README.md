# features/wine 폴더 나누기

한 폴더에 37개가 평평하게 쌓여 있어서, 파일 이름만 보고는 이게 손으로 적은 표인지
화면인지 DB 를 건드리는 코드인지 알 수 없었다. **바꿀 때 무엇을 조심해야 하는지가
다른 것들**을 갈라 둔다.

| 폴더 | 무엇이 있나 | 바꿀 때 |
|---|---|---|
| `curation/` | 사람이 손으로 적어 넣은 표 — 산지·생산자·품종 소개, 국내 적정가, 나라 이름 | 사실은 웹으로 확인하고 적는다. **확인 안 된 건 안 적는다** |
| `ui/` | 화면(`.tsx`) — 지도·색 고르개·와인 폼·각종 섹션 | `docs/theme.md` 의 토큰만 쓴다. 390px 에서 확인한다 |
| `db/` | Prisma 를 직접 부르는 조회·수정 | 여기서만 DB 를 만진다. 라우트는 이걸 부른다 |
| (루트) | 순수 함수 — 색·향·맛 계산, 블렌드, 검색 조립, 스키마 | 테스트가 붙어 있다. 화면도 DB 도 모른다 |

새 와인을 추가할 땐 `curation/` 넷을 채운다 — `/add-wine` 커맨드가 그 순서를 안내한다.

**루트에 남긴 것 중 헷갈릴 만한 둘**

- `aroma-palette.ts` 는 향 단어 표지만 `tasting-hints.ts`·`winemaking.ts` 와 한 몸으로
  테스트된다(예상에 뜨는 향이 팔레트에 다 있는지). 떼면 그 짝이 보이지 않는다.
- `winemaking.ts` 도 표를 들고 있지만 파싱·직렬화 로직이 본체다.
